Findings fixed during these runs:
 - facilitator settle latency varies from 2s to over 60s, worse in parallel: authorisation window raised to 120s, request timeout 100s
 - a settle that outlives the request is held as pending and recovered from the chain (AuthorizationUsed), never lost
 - recovery is scoped to the current session so a new session cannot be polluted by an older pending payment
 - one retry with a fresh signature after a transient 402 once the old nonce is confirmed unused
 - plain failures exclude a seller only for that call; only refusals and junk exclude it task-wide
