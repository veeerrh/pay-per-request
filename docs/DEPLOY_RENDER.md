# Public deployment on Render (free) with UptimeRobot

One free Render web service serves everything judges must reach over public HTTPS, at one address with its own `onrender.com` name:

```
https://<name>.onrender.com/                   dashboard and buyer console (Beacon)
https://<name>.onrender.com/registry/          registry page   (JSON: /registry/services, register: POST /registry/services)
https://<name>.onrender.com/atlas/countries?top=3&by=population
https://<name>.onrender.com/tremor/quakes?country=India&days=7&minMag=4.5
https://<name>.onrender.com/brief/brief        (POST)
https://<name>.onrender.com/relay/relay        (POST, the agent chain; /relay/payments shows its wallet)
https://<name>.onrender.com/overquote|redirect|hollow|offline/...   test vendors
https://<name>.onrender.com/gateway/health     health check (UptimeRobot pings this)
```

How it runs (`scripts/render-host.js`, `RENDER_FULL=true`): the registry and all sellers share one process; Beacon runs as a separate child process on a loopback port, and every other path is proxied to it. Beacon buys from the sellers over the **public HTTPS address** (`BEACON_LOCAL_ROUTES=false`), exactly like a judge's buyer. About 190 MB in total, inside the 512 MB free limit.

Secrets: the wallet key and operator token go to Beacon's child process only; Relay's key goes to Relay's own child process only (about 280 MB in total with Beacon and Relay). The host process, which runs the seller code, removes them from its own environment before loading any seller. Testnet wallets only; rotate `BEACON_PRIVATE_KEY` and `OPERATOR_TOKEN` after judging. A sellers-only mode (no `RENDER_FULL`, no keys) also exists and refuses to start if a key is set.

## 1. Deploy on Render (you do the account steps)

1. Sign in at <https://render.com> with GitHub and allow it to read `veeerrh/pay-per-request`.
2. **New > Blueprint**, name it `agentmarket`, pick the repo and the branch (`build/di06`, later `main`). Render reads `render.yaml`.
3. Fill the secrets Render asks for (it never reads them from the repo):
   - `BEACON_PRIVATE_KEY`: the Beacon testnet wallet key (the one whose address is `0xADb43a17Cb94d4125f45522d815060B58A71dcCb`), copied from your local `.env`.
   - `GEMINI_API_KEY`: Beacon's key. `ATLAS_GEMINI_API_KEY`, `TREMOR_GEMINI_API_KEY`, `BRIEF_GEMINI_API_KEY`: one key per seller. Leaving one empty is fine; that agent then answers rule-based.
   - `RELAY_PRIVATE_KEY`: the agent chain's own testnet wallet key (address in `config/addresses.json` as `sellers.relay`). Optional: leave it empty and Relay is simply not started or listed. If you set it, **fund that address with test USDC** at the Circle faucet first (Relay is paid only after it delivers, so it needs a working float of at least about 0.11 USDC). `RELAY_GEMINI_API_KEY` is optional.
   - `OPERATOR_TOKEN` is generated by Render. Read it in the service's Environment tab when you need "New session".
4. Deploy. The first build takes a few minutes. When the log shows `Beacon on :4100` and `registry seeded`, open `/gateway/health` (it should say `"beacon": true`).
5. If `registry seeded` is missing (the public address can need a moment), use **Manual Deploy > Restart**. Seeding is idempotent.
6. Open the address, run one example task, and check that the ledger rows have transaction links. This is the one test that proves Beacon-to-seller payments work over the public HTTPS path.

## 2. Keep it awake with UptimeRobot (free)

A free Render service sleeps after about 15 minutes without traffic and takes 30 to 50 seconds to wake.

1. Sign up at <https://uptimerobot.com> (free).
2. **Add New Monitor**: type *HTTP(s)*, URL `https://<name>.onrender.com/gateway/health`, interval *5 minutes*, email alerts on.
3. Optional second monitor on `/registry/services`.

A five-minute ping keeps the service awake. Free Render gives about 750 instance hours per month, enough for one service always on.

## Limits to know

- **Cold start:** if the service ever sleeps, the first request takes 30 to 50 seconds. Open `/gateway/health` shortly before judging.
- **Ephemeral disk:** free Render storage is wiped on every restart or redeploy. Listings come back (the registry is re-seeded at start). Beacon's ledger, task history and session start fresh, so **do not restart or redeploy during judging**. Do the final judged run, export the ledger CSV and keep `docs/evidence`, then leave it alone.
- **Standby:** keep a laptop tunnel as a second address (`npm run tunnel -- cloudflared`).
- **Public dashboard:** anyone with the address can run tasks, so the spending caps stay on (per-task budget cap, 6 tasks per minute, maximum price 0.10 USDC). The test wallet is small; refill it from the Circle faucet if it runs low.
- **Not on Vercel:** Vercel runs short serverless functions, not a long-running Node server with local databases.

## Local rehearsal (no Render needed)

```
RENDER_FULL=true PORT=10000 PUBLIC_BASE_URL=https://example.test node -r dotenv/config scripts/render-host.js dotenv_config_path=.env
node scripts/reference-buyer.js "http://localhost:10000/atlas/countries?top=1" BEACON_PRIVATE_KEY
```

Checked on 2026-10-17: dashboard, API, registry and the Fraud Lab roster answer through the one address; a real x402 payment settled through the single-process host. Not testable without a public address: Beacon paying the sellers over the HTTPS path (step 6 above).
